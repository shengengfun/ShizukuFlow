原生 / Web 归属

判据：这块 UI 会不会在 1 秒内被重绘 60 次？会，就必须原生。
原生 (Qt)
  • 预览舞台 — 每帧要贴一张 1920×1080 纹理，走 WebView 必然掉帧，且窗口抓图会出 GDI 伪黑
  • 时间轴（含图层列表 + 波形） — 参考 AE / Vegas：图层列表就在轨道左边， 逐行天然对齐，没有第二处。鼠标拖动要跟手，Aegisub 手感在这里
上一版把图层树放在左栏下方、时间轴左边又放一套标签栏，是同一个东西做两遍。 现在合并：左侧就是图层列表。
Web (WebView)
  • 部件库 — 内容密集、样式改版频繁，排版用 CSS 比 Qt 布局快一个数量级
  • 检查器 — 每个部件的参数控件由 schema 生成，天然是「数据驱动 UI」，最适合 Web
最难的一处：拖拽
  • 从部件库（Web）拖到时间轴（原生）要跨进程。两条路：
    ① Web 发 drag.begin 命令，原生接管后续拖拽；
    ② 拖拽全程在 Web 侧完成，落点算成时间值再提交 part.apply。
  • 倾向 ②：命令层本来就是纯数据，落点是一个时间戳，不依赖原生坐标。
注：现有 state/commands.ts 的命令层已是纯数据 + JSON 往返守卫， 跨 Qt / WebView 边界可直接复用，面板代码不用改。
