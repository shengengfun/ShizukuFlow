> 工作目录 `d:/Project/ShizukuFlow`。

## 为什么要做

项目要做一套「演出部件系统」，每个部件需要一批**参数默认值**（`blur` 该给多少、`bord` 该给多少、`\t` 的加速曲线通常怎么配）。
凭空拟定必然不对味。而 `karaoke-templates/` 下有 **496 个真实 ASS 演出模板**，答案就在里面。

你的活：把它们统计成一张表，供主控写进部件参数体系。

## 输入

```
d:/Project/ShizukuFlow/karaoke-templates/ASS Template/*.ass      （主战场，496 个文件的主体）
d:/Project/ShizukuFlow/karaoke-templates/绝对能入门的字幕模板/**/*.ass
```

只统计 `.ass`（不要统计 `.rar` / `.ttf` / 图片）。目录里有中文名，注意脚本用 UTF-8 读取。

## 你要产出

### 1. `scripts/ass_stats.mjs`

一个独立 Node 脚本（不引第三方依赖，只用 `node:fs`）。职责：遍历上述目录 → 解析每条 `Dialogue:` 行的 override 块 `{...}` → 提取标签 → 输出统计 JSON 到 stdout。

解析要点（照做）：

- 只取 `Dialogue:` 行，忽略 `Comment:`
- 标签形式：`\name` 或 `\name(arg1,arg2,...)`，参数可能为空、可能是小数
- 同一个 `{}` 块里可能挤着十几个标签
- **不要**尝试解析 `\t(...)` 内部嵌套的标签为顶层标签（`\t` 内部单独统计）
- 遇到解析不了的行就跳过并计数，不要抛错

### 2. `docs/CORPUS_STATS.md`

用上一步的 JSON 写出的报告，结构固定：

```md
## 1. 概览
- 扫描文件数 / 解析成功数 / Dialogue 行总数 / 跳过的行数

## 2. 标签频次 Top 30
| 排名 | 标签 | 出现次数 | 覆盖文件数 |
（按出现次数降序；覆盖文件数 = 有多少个文件至少用了它）

## 3. 数值参数分布
针对这些标签给出 最小 / P25 / P50 / P75 / 最大 和 最常见的 5 个取值：
\blur \be \bord \shad \fad(前两参) \t(t1-t2 时长与 accel) \fs \fscx \fscy \fr \frz

## 4. 建议默认值（20 条）
形如：`blur: 2.0  ← P50，62% 的模板落在 0~4`
每条必须标注依据（分位数或频次），不许凭感觉写。

## 5. 附录：抽样核对
随机 3 个文件，各贴 2 条原始 Dialogue 行（原文照抄），并写出你对它解析出的标签列表 —— 供主控核对脚本没跑偏。
```
